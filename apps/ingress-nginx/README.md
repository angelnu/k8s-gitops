# ingress-nginx - retirement & migration analysis

> **Note**: this document does NOT affect deployments (`.sourceignore` excludes `*.md`).
> It is the decision record (ADR-style) for replacing ingress-nginx.

## Context

- The [kubernetes/ingress-nginx](https://github.com/kubernetes/ingress-nginx/) project is **retired**:
  [announced 2025-11-11](https://kubernetes.io/blog/2025/11/11/ingress-nginx-retirement/), best-effort
  maintenance until **March 2026**, repository archived (moved to `kubernetes-retired`). Since then there are
  **no releases, no bugfixes and no security patches**.
- We run chart `4.15.1` / controller `v1.15.1` (the final maintenance line).
- Scope: ~**87 hosts** across ~**40 apps**, mostly generated by bjw-s `app-template` HelmReleases.

## Feature inventory (what we actually use)

### Global (ingress-nginx ConfigMap)

| Feature | Detail |
|---|---|
| **authentik global forward auth** | `global-auth-url` (outpost `/auth/nginx`), `global-auth-signin`, `global-auth-response-headers` (Set-Cookie + `X-authentik-*`), `global-auth-snippet` |
| **Group/user enforcement via Lua** | `server-snippet` with `access_by_lua_block` checking `$required_usernames` / `$required_groups` (403 on mismatch) |
| **auth_request_set variables** | global `location-snippet`: `$authentik_username/groups` from outpost response headers |
| **Custom error pages** | `custom-http-errors: 404,401,403,500,503` + `defaultBackend` (`billimek/custom-error-pages`) |
| **Tuning** | `proxy-buffer-size: 16k` (authentik), `proxy-body-size: 4000m`, hsts, resolver, `annotations-risk-level: Critical`, `allowSnippetAnnotations` |
| **Default class** | `watchIngressWithoutClass: true` + `ingressClassResource.default: true` (apps don't set `ingressClassName`) |

### Per-ingress annotations

| Annotation | Apps |
|---|---|
| `enable-global-auth: "false"` (opt-out of global authentik auth) | ~15 apps (public/internal endpoints that must stay open) |
| `server-snippet` (raw NGINX: `server_tokens off`, `proxy_hide_header`, `proxy_intercept_errors off`, `.well-known` rewrites, `location` blocks with `allow`/`deny`/`try_files`/`return`) | nextcloud (app + ingress-home) |
| `configuration-snippet: auth_request_set $required_groups 'casa_editors'` (consumed by the global Lua block) | esphome (x2), mealie, home-assistant-editor |
| `proxy-body-size` (4G / 8000m) | nextcloud, photoprism, openccu, unifi, tt-rss, forgejo, paperless |
| `proxy-read-timeout` / `proxy-send-timeout` (3600 / 600) | authentik, nextcloud talk, whiteboard, paperless |
| `whitelist-source-range` | apache-musicindex, music-assistant |
| `backend-protocol: HTTPS` | reverse-proxy (x9), apache-musicindex, unifi |
| `ssl-redirect: "false"` | home-assistant (Reolink integration pushes via http) |
| `upstream-hash-by: "$arg_WOPISrc"` | nextcloud collabora (WOPI document affinity; collabora autoscaling min 1 replica) |
| `hajimari.io/*` | dashboard discovery (hajimari reads **Ingress only**) |
| cert-manager TLS | via `extraArgs.default-ssl-certificate` + ingress `tls` sections |

### Infrastructure

- MetalLB `LoadBalancer` service with `externalTrafficPolicy: Local` (source-IP preservation, `metallb.io/loadBalancerIPs` annotation)
- WebSockets (home-assistant uses `nginx.org/websocket-services` - an F5 annotation that ingress-nginx simply ignores; websockets work by default there)

## Option 1 - OpenShift Router (HAProxy) - ❌ BLOCKED

The cluster already runs the OpenShift Ingress Operator (`apps/openshift-ingress-operator`). Reusing it would
avoid a new component, **but**:

| Requirement | OpenShift Router | Verdict |
|---|---|---|
| Forward auth / auth_request (authentik) | ❌ No equivalent. OpenShift pattern = OAuth proxy sidecar **per app** | **Blocker** |
| `server-snippet` / `configuration-snippet` (NGINX directives) | ❌ No snippet support at all | **Blocker** |
| `.well-known` rewrites / location `deny` blocks | ❌ Only `rewrite-target` per route, no conditional/location logic | **Blocker** |
| Custom error pages | ❌ Not supported | Blocker |
| `upstream-hash-by` | ❌ Only `balanceAlgorithm` (source/ip, roundrobin) | Blocker |
| `whitelist-source-range` | ✅ `haproxy.router.openshift.io/ip_whitelist` | OK |
| Timeouts / backend HTTPS | ✅ `haproxy.router.openshift.io/timeout`, route `tls.termination: reencrypt` | OK |

### Licensing

- The OpenShift Router ships with OKD — fully open source, no license.

**Verdict: discarded.** Migrating would require redesigning authentication for every protected app (OAuth proxy
sidecars) and dropping the nextcloud NGINX logic. It only makes sense as a fallback if the other options fail.

## Option 2 - F5 NGINX Ingress Controller (`nginx-inc/kubernetes-ingress`) - ✅ feasible (effort: medium)

Same NGINX engine (same directive semantics), **actively maintained by F5**, supports both the standard Ingress
API (with its own `nginx.org/*` annotations) and `VirtualServer` CRDs.

| Our feature | F5 NIC equivalent | Gap |
|---|---|---|
| `server-snippet` (nextcloud) | `nginx.org/server-snippets` annotation / `VirtualServer.spec.server-snippets` ([documented migration mapping](https://www.f5.com/company/blog/nginx/migrating-from-community-ingress-controller-to-f5-nginx-ingress-controller)) | none - same NGINX directives |
| `configuration-snippet` | `nginx.org/location-snippets` | none |
| `proxy-body-size`, read/send timeouts, `whitelist-source-range`, `backend-protocol`, `ssl-redirect`, `websocket-services` | same-named `nginx.org/*` annotations (home-assistant already uses `nginx.org/websocket-services`) | none |
| Global config | `GlobalConfiguration` CRD (`http-snippets` etc.) | partial - no `global-auth-url` |
| **Global auth + opt-out** (`global-auth-url` + `enable-global-auth: false`) | ❌ no global auth. Per-VS `auth_request` via snippets, or native **OIDC policy (NGINX Plus - commercial license)** | **gap** - auth becomes opt-in per VS |
| **Lua `access_by_lua_block`** (required groups) | ❌ F5 NIC ships **no lua module** | **gap** - must move group enforcement into authentik policies |
| Custom error pages | `errorPages` on VirtualServer/Route (per route); custom default server | partial (per-route, not global) |
| `upstream-hash-by: $arg_WOPISrc` | ❌ no query-param hashing; `sessionPersistence` (cookie) available | gap - keep collabora at 1 replica or accept cookie affinity |
| hajimari dashboard | ✅ still Ingress-based | none |
| cert-manager | ✅ standard Ingress TLS | none |
| MetalLB / source IP | ✅ LoadBalancer + `externalTrafficPolicy` | none |

### Licensing

- F5 NIC ships in two editions: **OSS** (Apache-2.0 controller + NGINX OSS engine, permissively licensed,
  actively maintained with public community calls) and **NGINX Plus** (paid F5 subscription).
- The **OSS edition covers everything we need**: `nginx.org/*` annotations, snippets, `GlobalConfiguration`,
  `VirtualServer`/`errorPages`, sticky-cookie session persistence, hash-based load balancing.
- **Requires a paid NGINX Plus license**: the **native OIDC policy** (the cleanest auth replacement) and the
  extra session-persistence methods (`sticky route`/`sticky learn`).
- => with the OSS edition, authentik auth stays via `auth_request` snippets (forward auth, works in OSS) —
  **no license purchase strictly required**, but the OIDC-native path is paywalled.

### Migration high-level

1. **Prerequisite**: move the "required groups" enforcement from the proxy into **authentik** (bind group
   policies per application). This removes the only hard NGINX-Plus/Lua dependency and simplifies both options.
2. Deploy F5 NIC **alongside** ingress-nginx with a separate `ingressClass` (e.g. `f5-nginx`) and its own
   LoadBalancer IP (MetalLB).
3. Migrate **app by app**: in each HelmRelease rewrite `nginx.ingress.kubernetes.io/*` annotations to their
   `nginx.org/*` equivalents (mechanical, 1:1 for most). Apps needing auth get explicit `auth_request` snippets
   or an OIDC policy. Verify each app behind the new class before switching its DNS/ingress.
4. Recreate global pieces: custom error pages (per-VS `errorPages` or default server), timeouts, buffer sizes
   via `GlobalConfiguration`.
5. Cut over the LB IP / DNS, then decommission ingress-nginx (chart + `default-backend` + SCC).

## Option 3 - Gateway API (Envoy Gateway or Traefik) - ✅ feasible (effort: high, future-proof)

The Kubernetes-blessed successor ([recommended in the retirement announcement](https://kubernetes.io/blog/2025/11/11/ingress-nginx-retirement/)).
Implementation candidates: **Envoy Gateway** (richest policy CRDs) or **Traefik** (middleware ecosystem).

| Our feature | Gateway API equivalent | Gap |
|---|---|---|
| Ingress per app | `HTTPRoute` (+ `parentRefs` to a `Gateway`; replaces "default class" - explicit attachment) | mechanical rewrite; **bjw-s app-template supports `route:`/HTTPRoute natively** |
| Global auth + opt-out | `SecurityPolicy.extAuth` (Envoy `ext_authz`; **authentik documents an Envoy forward-auth mode**) targeted at the HTTPRoute -> auth becomes **opt-in per route** (no annotation opt-out needed) | model inversion: routes without the policy stay open (matches our `enable-global-auth: false` set) |
| Lua group enforcement | ❌ | same mitigation as Option 2: authentik policies |
| `server-snippet` (nextcloud) | `HTTPRoute` filters: `URLRewrite` (`.well-known` rewrites), `RequestRedirect` (carddav/caldav 301), `ResponseHeaderModifier` (`proxy_hide_header X-Powered-By`) | `location` deny/allow blocks -> dedicated deny route pointing to a 403 backend (Envoy Gateway direct response) |
| Custom error pages | Envoy Gateway: ❌ no direct equivalent; Traefik: `errors` middleware | partial (per-route middleware) |
| `proxy-body-size` | Envoy/Traefik **stream** large bodies by default (no fixed 4G/8000m limit needed) | none - actually simpler |
| read/send timeouts | `HTTPRoute.timeouts.backendRequest` / `BackendTrafficPolicy` (EG) / Traefik `serversTransport` | none |
| `whitelist-source-range` | Envoy Gateway: SecurityPolicy/client-IP filtering; Traefik: `ipAllowList` middleware | implementation-specific |
| `backend-protocol: HTTPS` | `BackendTLSPolicy` | none |
| `ssl-redirect: "false"` | HTTPRoute does not redirect by default | none |
| `upstream-hash-by: $arg_WOPISrc` | ❌ consistent-hash supports cookie/header/sourceIP, not query params | gap - same mitigation as Option 2 |
| **hajimari dashboard** | ❌ hajimari discovers **Ingress only** (gethomepage has an open request too) | **gap** - manual service config in hajimari or replace the homepage app |
| cert-manager | ✅ Gateway API support (Gateway shim) | none |
| MetalLB / source IP | ✅ Envoy/Traefik Service type LoadBalancer | none |

### Licensing

- **Envoy Gateway**: Apache-2.0, no commercial tier — every feature we need (SecurityPolicy `extAuth`, JWT,
  `BackendTrafficPolicy`, `ClientTrafficPolicy`) is in the open source edition.
- **Traefik**: MPL-2.0 — the middlewares we need (`forwardAuth`, `ipAllowList`, `errors`, buffering) are in
  OSS Traefik; Traefik Hub/Enterprise exists but is **not** required.
- Gateway API CRDs: Apache-2.0 open standard.
- => **zero licenses** for this option.

### Migration high-level

1. **Prerequisite** (shared with Option 2): move group enforcement into authentik policies.
2. Install Gateway API CRDs + implementation **alongside** ingress-nginx; create a `Gateway` with its own
   MetalLB IP (test with a dummy app first).
3. Migrate **app by app**: switch each HelmRelease from `ingress:` to `route:` (HTTPRoute) in the bjw-s
   app-template values; add a `SecurityPolicy` (extAuth -> authentik outpost, envoy mode) to protected routes;
   express nextcloud rewrites as HTTPRoute filters.
4. Adapt hajimari: configure services manually (or switch to a Gateway-aware dashboard).
5. Cut over the LB IP / DNS, then decommission ingress-nginx.

## Comparison

| | Option 1 (OpenShift Router) | Option 2 (F5 NIC) | Option 3 (Gateway API) |
|---|---|---|---|
| Blockers | **Auth + snippets = blocked** | none (2 gaps with mitigations) | none (3 gaps with mitigations) |
| Effort | n/a | medium (annotation rewrite, same engine) | high (route + policy model) |
| NGINX parity | ❌ | ✅ same engine, snippets port 1:1 | rewrites re-expressed as filters |
| Auth model change | redesign (OAuth proxies) | per-VS auth_request | per-route SecurityPolicy (cleanest) |
| Maintained / future | ✅ (Red Hat) | ✅ (F5) | ✅ (standard) |
| hajimari dashboard | ✅ | ✅ | ❌ needs manual config/replacement |
| OIDC native option | via OAuth proxy | only with NGINX Plus license | EG SecurityPolicy JWT/OIDC (OSS) |
| **License cost** | none (OKD) | none with OSS edition (native OIDC = paid NGINX Plus) | **none** |
| Open source purity | ✅ (OKD) | ⚠️ OSS edition OK, best path (native OIDC) is paywalled | ✅ 100% open source |
